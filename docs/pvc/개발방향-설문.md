# 개발 방향 설문 (기획 초안 도구)

> **권장 자료입니다. PVC 사용의 필수 조건은 아닙니다.**  
> 이 파일은 **따로 받아 복사**해 두고, 기획 초안을 쓰면서 Agent가 제품을 정확히 이해하도록 돕는 질문지입니다.  
> 답변이 구체적일수록 작업 지시가 정확해지고 추측·재작업이 줄어듭니다.

| 항목 | 내용 |
|------|------|
| 대상 | 비개발자·비전문가·기획자·창업자·개발 의뢰자 |
| 목적 | 이해하기 쉬운 질문으로 **구체적이고 정확한 개발 방향**을 끌어내기 |
| 사용법 | 저장소에서 복사·다운로드 → 답변 작성 → Agent/개발자에게 제공 |
| 웹 폼 | [라이브](https://paakseongjin.github.io/perfect-vibe-coding/survey/) · [`개발방향-설문-폼.html`](./개발방향-설문-폼.html) — 브라우저에서 작성 후 Markdown/JSON 내려받기 |
| 다음 단계 | 답변을 `.cursor/rules/project/project-context.mdc`와 `CODEMAP.md` 초안에 요약 반영 (권장) |

## 언제 어느 정도까지 쓰나 (권장 등급)

| 모드 | 이런 때 | 권장 작성 범위 |
|------|---------|----------------|
| **Quick** | 실험, 단일 화면, 짧은 프로토타입 | 아래 Quick 4문항만 |
| **Standard** | MVP, 실서비스, 팀 프로젝트 | 이 문서 전체 (1~11장) |
| **High Risk** | 로그인·결제·민감정보·DB·배포·대규모 변경 | 전체 설문 + Feature Brief + 작업 전 승인 |

PVC는 설문 없이도 `project-context`만으로 시작할 수 있습니다.  
다만 **기획이 흐리면 Agent도 흔들리므로**, 가능하면 설문을 채워 제공하세요.

### Quick 4문항 (빠른 시작용)

| # | 질문 | 답변 |
|---|------|------|
| Q1 | 무엇을 만드나요? (한 문장) | |
| Q2 | 누가 쓰나요? | |
| Q3 | 형태는? (웹 / 모바일웹 / 앱 / 랜딩 / 관리자 / 기타) | |
| Q4 | 이번에 하지 말 것·절대 금지 (없으면 `없음`) | |

Quick만 채운 뒤 Agent에게:

```text
Quick 설문 답변을 project-context에 반영해 줘.
큰 구현 전에 짧은 계획만 먼저 보여 줘.
```

### Standard 이상 — 권장 체크 (강제 아님)

- [ ] 1장 제품 한 줄 목적  
- [ ] 2장 누가 쓰는지  
- [ ] 3장 첫 버전(MVP) 기능  
- [ ] 5장 로그인·개인정보 여부  
- [ ] 8장 Non-goals

## 작성 방법 (먼저 읽기)

1. **모르는 항목은 솔직히 `모름` / `나중에` / `추천 부탁`**이라고 쓰세요. 빈칸보다 낫습니다.  
2. **기술 용어를 몰라도 됩니다.** “카카오톡처럼 로그인”, “엑셀처럼 목록”처럼 일상어로 적어도 됩니다.  
3. **지금은 필요 없는 것**과 **나중에 하고 싶은 것**을 나누어 적으세요.  
4. 선택지가 있으면 해당 번호·문구를 남기거나, 여러 개면 모두 표시하세요.  
5. 답변은 이 파일에 바로 채우거나, 복사본(`개발방향-설문-답변.md`)을 만들어도 됩니다.  
6. 작성이 끝나면 Cursor Agent에게 이렇게 전달하세요.

```text
docs/pvc/개발방향-설문.md (또는 내 답변 파일)을 반영해
project-context.mdc와 CODEMAP 초안만 제안해 줘.
코드 구현은 내가 승인한 뒤에만 진행해.
```
