# 작업 전·중·후 안전 프로토콜

## 1. 작업 시작 전 필수 절차

코드 작성 또는 수정 전에 반드시 다음 절차를 수행한다.

1. 사용자의 요청을 기능 목표, 변경 대상, 완료 조건으로 정리한다.
2. 관련 규칙 파일, 운영 맵, 아키텍처 문서, 디자인 문서를 먼저 읽는다.
3. 수정 대상 파일과 연결된 화면, 컴포넌트, API, 데이터 모델, 테스트를 식별한다.
4. 데이터 유실, 연동 장애, 권한 오류, 렌더링 오류, 스타일 충돌 가능성을 점검한다.
5. 변경 범위와 작업 단계를 사용자에게 사전 보고한다.
6. 영향이 크거나 요구사항이 모호한 경우에는 구현 전에 반드시 질문하고 승인을 기다린다.
7. 승인되지 않은 기능 추가, 대규모 리팩터링, 데이터 구조 변경, 라이브러리 교체, 디자인 전면 개편을 임의로 수행하지 않는다.

## 3. 변경 최소화 원칙

- 요청한 문제를 해결하기 위해 필요한 최소 파일만 수정한다.
- 파일 전체를 재작성하지 않는다. 기존 구조와 동작을 보존하며 필요한 부분만 정밀 수정한다.
- 기존 기능을 삭제하거나 축소할 가능성이 있는 변경은 명시적 승인 없이는 수행하지 않는다.
- 자동 포맷팅, 의존성 업데이트, 파일 이동, 이름 변경은 영향 범위가 크므로 작업 범위에 포함되었을 때만 수행한다.

## 4. 작업 중단 및 질문 조건

아래 조건 중 하나라도 발생하면 즉시 구현을 멈추고 현재 상태, 위험, 선택지를 사용자에게 보고한다.

- 요구사항이 여러 방식으로 해석될 수 있는 경우
- 데이터 삭제·변환·마이그레이션이 필요한 경우
- 기존 기능의 동작 변경 가능성이 있는 경우
- API, 인증, 권한, 개인정보, 결제, 외부 서비스 연동에 영향을 주는 경우
- 테스트가 없거나 검증 환경이 없는 핵심 로직 변경인 경우
- 기존 코드의 의도나 참조 관계를 확실히 파악할 수 없는 경우
- 디자인 시스템 또는 아키텍처 규칙 간 충돌이 있는 경우
- 작업 범위가 최초 요청보다 커지는 경우
- 되돌리기 어려운 변경이 필요한 경우
