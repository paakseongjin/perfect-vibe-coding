# 운영 맵(CODEMAP) 유지

## 1. 운영 맵 의무화

- 프로젝트 루트에 `CODEMAP.md` 또는 동등한 운영 맵 문서를 유지한다.
- 운영 맵에는 최소한 다음 정보를 기록한다.

  1. 프로젝트 목적과 주요 사용자
  2. 기술 스택 및 실행 방법
  3. 최상위 폴더와 주요 파일의 역할
  4. 화면, 기능, API, 데이터베이스, 외부 서비스의 연결 관계
  5. 핵심 진입점과 주요 데이터 흐름
  6. 빌드, 테스트, 배포, 백업, 복구 방법
  7. 환경 변수와 비밀값의 관리 위치, 단 실제 비밀값은 기록하지 않음
  8. 주요 의존성, 버전 정책, 변경 시 주의사항
  9. 알려진 제한사항, 기술 부채, 후속 개선 과제

## 2. 변경 시 최신화

- 새 폴더, 새 기능, 새 API, 새 데이터 모델, 새 환경 변수, 새 외부 연동을 추가·변경·삭제하면 작업 완료 전 운영 맵을 함께 최신화한다.
- 운영 맵의 내용과 실제 코드가 불일치하면 코드 변경 완료로 간주하지 않는다.
- 디자인 시스템 변경, 구조적 변경 후에도 관련 운영 맵을 함께 갱신한다.
