# Perfect Vibe Coding (PVC)

**말로 웹·앱을 만드는 사람을 위한 Cursor 작업 운영 체제**

Cursor 프로젝트에 **복사해 쓰는 Rules·Skills·문서 템플릿**입니다.  
AI 에이전트가 안전하고 일관된 방식으로 작업하도록 돕습니다.

> **빠른 바이브 코딩**은 유지하고, **실무에서 버틸 수 있는 안전·일관성·문서**를 기본값으로 만듭니다.

---

## 처음 10분만 이렇게 하세요

1. 아래 **설치 단위** 중 하나를 고른다 (처음이면 **권장 설치**).  
2. (강력 권장) [`docs/pvc/개발방향-설문.md`](./docs/pvc/개발방향-설문.md) 의 **Quick 4문항**만 채운다 — 필수는 아님. 실험·랜딩은 Quick으로 충분.  
3. `.cursor/rules/project/project-context.mdc` 에 제품·스택·금지·검사 명령을 짧게 채운다. (예시는 지우고 내 값으로)  
4. Cursor에서 폴더를 연다.  
5. Agent에게 CODEMAP을 요청한다 (코드가 없어도 됨):

```text
아직 코드가 거의 없는 새 프로젝트야.
루트에 CODEMAP.md 초안만 만들어 줘.
최소 목차: 목적, 사용자, 스택(모름이면 빈칸), 폴더 계획, 화면 목록, 하지 말 것, 다음 할 일.
구현·파일 대량 생성은 하지 마.
```

6. 작은 문구 수정 한 번으로 동작을 시험한다.

막히면: `PVC README 처음 10분 단계부터 한글로 도와줘`

## 설치 단위 (중요)

| 단위 | 복사할 것 | 할 수 있는 것 | 빠지면 |
|------|-----------|---------------|--------|
| **최소** | `.cursor/rules/` + `.cursor/skills/` | Agent 규칙·스킬 동작 | 설문·템플릿·한글 해설 경로가 프로젝트에 없음 (원본 PVC 저장소를 열어 참고) |
| **권장** | 최소 + `docs/pvc/` + `docs/templates/` | 설문·체크리스트·Brief까지 프로젝트 안에서 작성 | 깊은 한글 해설·카탈로그는 없음 |
| **전체** | 권장 + `docs/pvc-guide/ko/` + `docs/references/` | 해설·외부 출처까지 오프라인 | — |

- **A.** 이 저장소 전체를 fork/복사해도 됩니다 (전체가 가장 단순).  
- **B.** 기존 앱에는 보통 **권장 설치**를 복사하세요.  
- 라이선스: [`LICENSE`](./LICENSE) (MIT) — 복사·수정·재배포 가능.

## PVC가 막아 주는 문제

| 문제 | 결과 | PVC |
|------|------|-----|
| 기준이 매번 바뀜 | 구조·스타일 난잡 | 고정 규칙 + 사실 카드 |
| 위험한 수정 | 데이터·로그인 사고 | 위험도 등급 + 승인 |
| 문서 없음 | 나중에 이해 불가 | CODEMAP 습관 |
| 디자인 분열 | 페이지마다 다른 UI | 디자인 시스템 우선 |
| 스킬 남용 | 충돌·비용 | **원칙만** 변환, 통째 설치 금지 |
| 토큰 낭비 | 매 채팅 과금 | 상시 규칙 2개만 |

## 핵심 원칙

1. **상시 규칙은 얇게** — Always는 안전 헌법 + 프로젝트 사실만.  
2. **상황 규칙은 정확하게** — 연 파일·작업 종류에 맞는 규칙만.  
3. **실행은 영어, 해설은 한글** — Agent용은 EN, 사람용은 KO.  
4. **유명해도 통째 설치 금지** — 필요한 원칙만 변환.  
5. **한 주제는 한곳에** — Rules / Skills / Docs / Templates / References.  
6. **보안·데이터 최우선**  
7. **기획 설문은 권장** — 비개발자는 먼저 **Quick 4문항** ([`개발방향-설문.md`](./docs/pvc/개발방향-설문.md)).

| 모드 | 언제 | 얼마나 |

```text
큰 구현 전에 짧은 계획만 보여 줘.
```

## 프로젝트 사실 카드

`.cursor/rules/project/project-context.mdc` — Agent가 매 채팅에 보는 **짧은** 카드.  
템플릿의 Next/Prisma 등은 **예시**입니다. 쓰지 않으면 지우고 채우세요.

| 넣을 것 | 예 |
|---------|----|
| 제품 한 줄 | 동네 카페 예약 웹앱 |
| 사용자 | 사장님 + 손님, 모바일 |
| 스택 | 쓰는 기술만 |
| 금지 | 운영 DB 직접 쓰기 금지 |
| 검사 명령 | lint / test / build |

## 더 알아보기 — Rules / Skills가 켜지는 방식

지도: [`RULES_MAP.md`](./RULES_MAP.md) · 검증: [`CHECKLISTS.md`](./docs/pvc/CHECKLISTS.md)

| 스위치 | 의미 |
|--------|------|
| Always (2개) | `core/00`, `project-context` |
| Globs | 관련 파일을 만질 때 |
| Agent / Skill | skill-router 등 |
| Manual | migration, incident |

**위험도(정본은 `core/00`):** Low 바로 수정 → Medium 짧은 계획 → High/Critical 승인 전 구현 금지.

한글 해설은 영어 실행 규칙을 이해하기 위한 보조 문서입니다.  
달라 보이면 **영어 실행 규칙**을 기준으로 하고, 오류면 Issue/PR로 고칩니다.

## 자주 묻는 질문

**Q. 설문을 꼭 써야 하나요?**  
A. 아니요. **Quick만이라도** 쓰면 Agent가 훨씬 정확해집니다.

**Q. `.cursor`만 복사해도 되나요?**  
A. 됩니다(최소 설치). 설문·체크리스트는 PVC 원본 저장소나 권장 설치를 쓰세요.

**Q. Next가 아니면요?**  
A. `project-context` 예시 스택을 지우고 바꾸면 됩니다.

**Q. 스킬을 많이 깔면?**  
A. 보통 손해입니다. 원칙만 가져오세요.
